# FS-21 · External or untrusted input accepted without bounds, sanitization or isolation

Client, bot, import or upload input reaches validators, DB columns, parsers and renderers with only happy-path handling: missing numeric/type bounds on JSON, isdigit gates, varchar overflow, one bad unit aborting a batch, over-broad regex/substring matches, heuristics that under-fit real noise, sanitizer bypasses, tar path traversal, ReDoS, verbatim text into agent-parsed documents, permissive security defaults (CORS, no throttle). Malformed input 500s or becomes a vulnerability.

**Triggers**
- a serializer/validator accepts nested JSON, id strings, amounts/counts, or bot-writable fields
- an import/sync from an external export or API, or a batch loop over many independent units
- a regex or substring match over free text, HTML, URLs or transcripts
- extracting archives, rendering stored HTML, embedding user text into markdown/LLM input, a new auth endpoint or a new settings default
- user-entered or imported dates and quantities that drive ledger posting (payment_date, purchase date, bank statement date, gallons_sold); ids and list items in LLM-authored JSON
- a single-item recovery/retry helper with early return reused inside a batch loop (bulk export to device contacts)
- a template literal inserts any variable, even a trusted constant, into SQL text
- csv.DictReader header keys matched by exact string (lowered but not stripped) in an upload/import validator, and the parser exists in more than one method

**Guards**
- Parametrize malformed-input tests per field (nested dict/list/bool, negative, oversized, non-ASCII digits) asserting 400, not 500
- Isolate each import unit in its own transaction/try and log failures; validate/truncate to column bounds; normalize names before matching
- Anchor and bound regexes; scope URL matchers to the external domain and test that own-domain URLs are excluded
- Route all HTML through the shared sanitizer, use safe archive extraction, flatten newlines in agent-parsed text, add throttles and an explicit prod CORS allowlist
- Add plausible-range date validators and cross-field checks (amount > 0 requires quantity > 0); clip to the minimum width of every column a value propagates into; coerce LLM-supplied ids and guard list item types
- Collect per-item results in batch loops and test N>1 where item 1 fails and items 2..N still succeed
- Route every dynamic SQL value through a $N placeholder and grep for template-literal SQL in review
- Test CSV input with header whitespace, a BOM, case variants and a blank extra column; grep for every sibling copy of the parser and fix them together (FS-62)
