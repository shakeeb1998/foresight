# FS-91 · Written claim in docs, comments or commit prose not re-derived from what it cites

Docstrings, whitepaper paragraphs, case source fields, adjudications and commit bodies state facts from the plan's prediction, from memory or from a copied note, not from a fresh run or a read of the source. Examples: 'this case now passes', 'this case proves end-to-end routing', a precedent's numbers, another file's note on wiring status. Reviewers catch the mismatch late, or it misdirects later planning.

**Triggers**
- writing a docstring, comment or doc sentence saying a named test or case passes or proves a behavior
- quoting another file's descriptive note (catalog notes, scope or wiring status) into new docs or a case's source field
- a commit body, adjudication or PR description citing numbers, thresholds or commit history from another document
- prose written in the same session as the plan that predicted the outcome

**Guards**
- Run the exact test or case and cite its result next to any 'now passes' claim; if it still fails, write the outcome as expected, not achieved
- Before describing what a case proves, trace the runner function it actually invokes and name that code path
- Re-verify any quoted state note against current code instead of copying it
- Open the cited document and quote its exact numbers and SHAs instead of paraphrasing from memory
