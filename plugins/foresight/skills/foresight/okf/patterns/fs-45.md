# FS-45 · Agent turn ends waiting on an unverified async mechanism

A (sub)agent hands its completion to something asynchronous it never verified (its own Monitor watcher, a wakeup timer, a blocking debug call, a resumed run) and ends idle, wedged or silent with uncommitted edits. The orchestrator then waits or assumes failure instead of checking git and test state directly. Release automation adds background pollers that shell out to helpers in /tmp which vanish between sessions and then fail silently every cycle, background uploads and scratch dirs from a previous session with no completion record, a background subagent that crashed at launch, and a laptop that sleeps mid-pipeline.

**Triggers**
- a worker's last action is starting a background run/Monitor and waiting for its notification
- a blocking call against a live server or browser that can hang
- a subagent silent for an unusually long time, or a promise of periodic updates on a timer
- a subagent backgrounds its own long command and yields; multi-hour fan-out state held only in process; a fix loop planned around resuming agents via SendMessage
- a background poll/loop shells out to a helper under /tmp or a scratch dir; resuming after hours or a session boundary on a background task's result; a long unattended release run on a laptop
- dispatching three or more long-running worktree agents at once
- an implementer has run many consecutive fix rounds in one session without committing (provider session/rate limits end it mid-round)
- background implementer agents running when the parent session may hit a usage limit; planning to resume a subagent via SendMessage
- a long-lived local service (mock server, dev app) started as an agent-harness background shell

**Guards**
- Instruct workers to run verification synchronously or poll results themselves, never ending a turn on their own watcher
- Background potentially hanging calls and poll with a timeout
- When a subagent stalls, check git status/log and test results directly before relaunching
- Put 'never background a command, run to completion' in every agent prompt template, checkpoint fan-out progress to a durable file, and confirm the resume tool is available before planning around it
- Keep automation helpers in the repo's scripts/, make poll loops exit non-zero when a helper is missing, check a dispatched agent's output file size/mtime shortly after launch, treat a missing completion record as unknown and re-verify against the target system (ASC/Play), and run caffeinate for long unattended runs
- Arm a per-worktree file-write staleness watch and check the session/rate budget before the fan-out
- Commit after each discrete fix and write self-contained round briefs so a fresh agent can resume a round if the previous one dies
- After any session restart check each in-flight worktree's git status before assuming work landed; hand off through a persisted report file a fresh agent reads, since SendMessage may be disabled
- Run long-lived services under launchd/systemd or in the user's terminal; harness background shells die at the harness time limit
