# FS-19 · Behavior change leaves dependent tests, drivers and mocks stale

A component's interaction model, a response shape, a default value, a permission class or a shared fixture changes, but the unit tests, MSW handlers, e2e drivers, seed helpers and specs that encoded the old behavior are not updated in the same change. With CI not running those suites they go silently red, and later sessions misread them as their own regressions or as baseline noise.

**Triggers**
- a shared component gains a hook, a confirm/apply step, a new underlying library, or a new default layout/copy
- a response shape changes (bare list -> paginated envelope) or a query hook moves to a scoped endpoint
- a default param value, permission class, or auto-provisioning behavior changes
- a stubbed fixture's real endpoint ships
- a permission class added to an existing endpoint; a patched symbol moved or renamed while tests use mock.patch string paths
- swapping a field's control type (Input to Select), flipping a form's default enum value, replacing a placeholder/disabled state with the shipped feature, or a global render change (currency glyph to SVG, exotic whitespace, DS required-asterisk markup) that exact-text specs and locale-paired EN/AR specs assert on

**Guards**
- Grep unit tests, MSW handlers, tests/e2e helpers/drivers and specs for the component/endpoint and update them in the same commit
- Run the dependent suites (the component's own tests plus every e2e spec that renders it) right after the edit
- When a stub goes live, convert fixture-based specs to live-API assertions
- Grep e2e specs and drivers for fill() on the field's testid, literal glyphs and the old rendered strings; make specs select non-default branches explicitly; update and run both locale variants of every touched spec
