# FS-117 · Refactor or rewrite silently drops behavior the original had

Extracting into a shared helper, consolidating files, renaming, or rewriting a body by hand rather than moving it loses steps (warm-up, classloader semantics, existence checks, dependency order, fields, docstrings) or smuggles logic changes into a 'mechanical' change. Nothing fails until the dropped behavior is needed.

**Triggers**
- extracting working code into a shared library or factory
- merging several files, or a 'rename only' task that also touches bodies
- rewriting a class/function body that has docstrings, guards or ordering

**Guards**
- Move code verbatim first, then diff old vs new and account for every removed line
- Keep rename-only commits free of body edits
- Diff task dependency order before and after a TaskGroup/factory extraction
- Run the original call path's tests against the refactored code
