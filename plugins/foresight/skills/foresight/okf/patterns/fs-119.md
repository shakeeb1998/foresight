# FS-119 · Consumer or edge patched to tolerate bad state instead of fixing the producer

When one producer emits inconsistent state, the fix lands in a shared consumer (per-table flag in a shared job, override in the optimizer), at the outermost presentation mapper, in the data to satisfy a validator, or as a hardcoded field list. Other consumers still see the bad state and shared code grows special cases.

**Triggers**
- a review says a shared job breaks on one new table/producer
- the quickest fix is a flag or field list in shared/downstream code
- a bug visible in one API surface that re-maps an upstream service

**Guards**
- Trace the bad value to the mutation that creates it and fix there
- Fix in the shared upstream service that every surface reads, not one edge mapper
- If a check fails on canonical data, fix the check, not the data
