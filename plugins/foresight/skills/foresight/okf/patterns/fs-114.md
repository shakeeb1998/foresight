# FS-114 · Git commit, reset or push run without checking the current branch and PR state

The agent commits, resets or pushes on whatever is checked out: directly on the base branch, on an unrelated feature branch, on a branch whose PR already squash-merged (recreating it), in a worktree on the wrong branch, or after switching back to base and writing follow-ups there. Partial commits leave imports to uncommitted files, and deleted worktrees keep holding branches.

**Triggers**
- about to commit/push via a UI action or a one-line command
- returning to a PR branch after hours or days
- the current branch name doesn't relate to the change, or is the base branch (dev/main)
- creating or removing a worktree; staging only some of the changed files

**Guards**
- Run git status -sb and gh pr view --json state,headRefName before every commit/push
- Never commit to the base branch; create a branch with --no-track from origin/<base>
- If the PR is merged, start a new branch from origin/<base>
- Check staged files import nothing unstaged (git stash -k && build) before a partial commit
- Remove worktrees with git worktree remove, then git worktree prune
