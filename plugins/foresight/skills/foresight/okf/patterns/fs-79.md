# FS-79 · Sync or offline state decided from an empty, transient or proxy remote signal

An offline-first sync engine treats what the remote returned as the whole truth: a prune step deletes local rows absent from the pull response, so an empty or partial response (transient failure, scope change) wipes the device's data; a guard against a 'suspiciously empty' response counts records while the backend always injects a builtin/sentinel record; the offline banner trusts NetInfo.isConnected (false negatives on the iOS Simulator, stale on devices) instead of probing the backend. Happy-path sync tests pass; users lose local data or see a false offline state.

**Triggers**
- a pull/sync step computes stale = local minus remote and deletes from that set
- a sanity guard uses list.length on a response that can contain builtin/system rows
- offline UI branches on NetInfo.isConnected or isInternetReachable alone
- a request gate (react-query onlineManager or similar) pauses every request on isInternetReachable

**Guards**
- Write the empty-response and error-response tests first and assert zero local deletions; treat an empty list as unknown and prune only on explicit tombstones or a confirmed per-row 404
- Exclude sentinel/builtin records before counting, and test the case where only the sentinel is present
- Drive offline UI from a real /health probe of the app's own backend, using NetInfo only as a hint
- Never use isInternetReachable as a hard request gate (it cannot succeed on the Simulator); gate on isConnected plus a real backend probe
