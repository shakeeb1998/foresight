# FS-118 · Sibling module copied wholesale without auditing what it carries

A new lambda, infra file, bucket, DQ suite or table is cloned from a sibling and keeps its baggage: unrenamed identifiers, import-time env reads for unset vars, IAM and env vars the new use never needs, legacy versioning state, deprecated patterns, layer placement and thresholds that fit the sibling only.

**Triggers**
- creating a file by copying a sibling module or 'exactly the same' resource
- a sibling resource with historical or legacy config
- per-platform suites or configs generated from one template

**Guards**
- After copying, grep for the sibling's name and walk each env var, grant and setting asking whether the new one reads it
- Check provider deprecations before copying a pattern
- Derive thresholds/config per target from its own data, not the sibling's values
